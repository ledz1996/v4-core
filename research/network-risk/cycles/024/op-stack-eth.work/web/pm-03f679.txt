font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">Base is committed to building in the open, which includes sharing detailed public postmortems when issues arise.</p>
<h2 class="text-[20px] md:text-[24px] leading-[28px] md:leading-[32px] font-base font-normal tracking-tight mt-10 text-black dark:text-white">Overview</h2>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">On June 25th and 26th 2026, Base mainnet experienced two block production outages. The first incident began at 11:47am EDT on the 25th, and lasted 116 minutes. The second started at 11:28am EDT on the 26th and lasted 20 minutes. The root cause was the same and they will be discussed together throughout this postmortem.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">The integrity of the chain was not compromised and all funds on Base were safe. Block production resumed safely after we mitigated the incident. This postmortem dives into the root cause, the impact, how we mitigated, and what we plan to improve moving forward.</p>
<h2 class="text-[20px] md:text-[24px] leading-[28px] md:leading-[32px] font-base font-normal tracking-tight mt-10 text-black dark:text-white">Root Cause</h2>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">We identified a bug in sequencer block-building logic that allowed stale journal state to persist after a transaction validation failure. An invalid transaction was received by the block builder and failed during execution, as expected, but erroneously did not clear the journal state that contained the accounts and storage slots that had been accessed.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">After that failed transaction, a valid transaction was received and executed before the journal was properly cleared. As a result of the inaccurate journal state, the valid transaction had a mismatch in the amount of gas charged. This caused a sequenced block that contained an invalid state transition, leading to a block that could not be accepted by any other nodes. The chain fully halted at this point.</p>
<h2 class="text-[20px] md:text-[24px] leading-[28px] md:leading-[32px] font-base font-normal tracking-tight mt-10 text-black dark:text-white">Impact</h2>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">During the 116 and 20 minute outages, Base experienced the following issues.</p>
<h3 class="text-[18px] md:text-[20px] leading-[26px] md:leading-[28px] font-base font-normal tracking-tight mt-6 text-black dark:text-white">Block Production</h3>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">Complete halt of new L2 blocks produced. The sequencer and validator nodes could not progress past the invalid block until sequencing was restored.</p>
<h3 class="text-[18px] md:text-[20px] leading-[26px] md:leading-[28px] font-base font-normal tracking-tight mt-6 text-black dark:text-white">Transaction Processing</h3>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">During the outage, new transactions that queued in the mempool were not included onchain. This caused the txpool to grow larger than what it could store, and reject newly submitted transactions. Requests submitting <code class="bg-bds-gray-5 rounded px-1.5 py-0.5 font-mono text-[0.9em] dark:bg-white/10">eth_sendRawTransaction</code> transactions to Base were receiving errors throughout this time.</p>
<h2 class="text-[20px] md:text-[24px] leading-[28px] md:leading-[32px] font-base font-normal tracking-tight mt-10 text-black dark:text-white">Mitigation</h2>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">The outage was fixed by applying a patch to the sequencers to ensure the journal state was properly updated during execution.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">The fix can be seen in this PR: <a href="https://github.com/base/base/pull/3806" target="_blank" rel="noopener noreferrer" class="group pointer-events-auto decoration-bds-gray-30 hover:decoration-bds-gray-80 text-black underline underline-offset-[3px] transition-colors dark:text-white">https://github.com/base/base/pull/3806</a></p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">Mitigation took longer than expected due to infrastructure conditions unrelated to the original bug. The sequencers in the active/passive cluster do consensus-layer sync rather than execution sync like validator nodes. A race condition in the engine reset feature prevented the sequencers from catching up to tip after being restarted. This affected only the sequencers, but was a separate bug we had to fix during mitigation.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">It is because of this second issue that the incident occurred again the following day. The issue can be seen here: <a href="https://github.com/base/base/pull/3805/changes" target="_blank" rel="noopener noreferrer" class="group pointer-events-auto decoration-bds-gray-30 hover:decoration-bds-gray-80 text-black underline underline-offset-[3px] transition-colors dark:text-white">https://github.com/base/base/pull/3805/changes</a></p>
<h2 class="text-[20px] md:text-[24px] leading-[28px] md:leading-[32px] font-base font-normal tracking-tight mt-10 text-black dark:text-white">Going forward</h2>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">Base is committed to building a platform for global finance, and will continue investing in the reliability and performance of the chain to live up to that mission. We recognize this incident caused disruption for users, builders, and node operators.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">We are using this incident to harden protocol fuzz testing practices and load testing harnesses to be able to more easily identify adversarial transaction patterns that could expose bugs like the one we saw here. In addition to operational and monitoring improvements, we expect these changes to improve resilience and will continue validating them in production and through testing.</p>
<p class="text-[15px] md:text-[16px] leading-[140%] font-base-text font-normal tracking-normal text-bds-gray-80 dark:text-bds-gray-20 leading-[170%]">Additionally, this case required validator nodes to be restarted in order to continue syncing. We intend to implement graceful recovery into base-consensus for faster and easier ecosystem recovery in these situations.</p>
